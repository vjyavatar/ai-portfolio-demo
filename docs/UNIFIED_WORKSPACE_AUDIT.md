# Celesys unified workspace audit

## Scope

Inventoried all 48 distinct tools in TAB_GROUPS, plus Active Trading and Today’s Setups. Scanned all 17 runtime static JavaScript files for syntax, all inline homepage scripts, and the complete Python API syntax tree. Reviewed navigation, source adapters, account gates, voice entry points and report lifecycle. This is not a line-by-line certification of every financial model or an audited trading-performance claim.

## Corrections and integration

- Main / now serves the unified existing app; /research remains compatible with a canonical pointing to /.
- Original calculations supply inline five-part briefs. No new LLM service is enabled.
- Removed broker credentials/OAuth adapter, broker UI prompts and status polling. Retired routes return 410. Existing deployment secrets are unused and were not read.
- India uses the existing NSE path, with no access-control evasion or fabricated premiums. SENSEX is correctly withheld from the NSE route because it is a BSE contract.
- Personal CSV inspection runs entirely in the browser, requires user-declared expiry and is labelled imported, not live. Public uninterrupted India data remains dependent on an available authorized source.
- Manual long-position plan allows zero lots when capital/risk cannot support one; no orders are sent. Contract multiplier must be provided by the user.
- The simplified trading view no longer destroys the original report/menu DOM.
- Repaired the truncated PWA script and changed service-worker navigation to network-first, avoiding a permanently stale homepage.
- Voice is opt-in, with mute, stop and symbol-confirmation before research. Existing assistant/terminal voices are preserved.

## Verification

161 focused Python/JavaScript checks pass (71 Python, 90 JavaScript). This includes prior trading regressions, adapters, all menu membership, permission boundaries, delayed responses, CSV formats, zero-lot sizing, voice controls, asset parity and broker removal. The final homepage ID uniqueness and generated-shell consistency checks pass. Browser-based visual QA and a live click-through of every permissioned financial engine were not available in this environment. API availability is checked after deployment; partial/missing fields are not represented as verified.

Post-deploy verification exposed a positional startup-injection mismatch after removing the broker argument. Startup now injects all three engines by keyword. A regression executes the actual start.py attach call and verifies each public route receives its intended supplier.

The live decision endpoint also exposed a NumPy boolean serialization defect. Decision outputs now pass through the existing numeric sanitizer before FastAPI encoding; NumPy 2 boolean names and nested array conversion are handled. The underlying trading calculations are unchanged.

The original analysis form is visible before the optional brief. Loaded charts can be reopened without rebuilding the report. Email-role tests execute the original role resolver and verify actual menu visibility for public, trading, full and admin roles.

Automated QA coordinator: `qa/audit.py`, with all 50 tools across six access profiles, declared route/function inventory, read-only live probes, Markdown/JSON evidence and CI browser fixtures. Browser fixture execution is tracked separately; see `qa/README.md`.
